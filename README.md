# International Conference Proceedings

A multi-conference academic publishing website built with Next.js, TypeScript, Firebase Authentication/Firestore, and Backblaze B2.

## Architecture

- Next.js App Router: public pages, SEO, structured metadata, and server-side rendering.
- Firebase Authentication: administrator sign-in.
- Cloud Firestore: conferences, articles, authors, messages, and audit-oriented metadata.
- Backblaze B2 S3-compatible API: PDF and poster object storage.
- Server-only Route Handlers: verify Firebase ID tokens and issue short-lived B2 presigned URLs.
- Netlify: deployment.

The B2 credentials remain server-side. The browser receives only short-lived presigned upload/download URLs. Backblaze documents that B2's S3-compatible API supports AWS SDKs and presigned URLs. See the official docs links at the end of this README.

- `/admin/login`

The admin link is not rendered in the public header/footer. Access is protected in the browser and all protected API routes validate a Firebase ID token plus the `admin` custom claim.

## 1. Install

```bash
npm install
```

## 2. Configure Firebase

1. Create a Firebase project.
2. Enable Authentication → Sign-in method → Email/Password.
3. Create a Firestore database.
4. Add a Web App and copy the web configuration into `.env.local`.
5. Create a service account and place its values in the server-side Firebase Admin variables.

Firebase's current Admin Node.js SDK requires Node.js 22 or newer according to the official setup documentation.

## 3. Configure Backblaze B2

Use the S3-compatible API. Create a B2 bucket and an application key with the minimum permissions required for the bucket.

Set:

```env
B2_ENDPOINT=https://s3.<region>.backblazeb2.com
B2_REGION=<region>
B2_BUCKET_NAME=<bucket>
B2_ACCESS_KEY_ID=<key-id>
B2_SECRET_ACCESS_KEY=<application-key>
```

For browser uploads, configure the bucket's CORS policy to allow `PUT` from:

- `http://localhost:3000`
- `https://conferencepublisher.online`
- `https://www.conferencepublisher.online` (if you use it)

Example policy is in `docs/b2-cors.json`.

Keep the bucket private in this design. Public content is delivered through short-lived signed URLs generated by the server.

## 4. Create the first admin

After signing in to your Firebase project, create the administrator account in Firebase Authentication.

Copy `.env.example` to `.env.local`, then run:

```bash
node scripts/set-admin-claim.mjs you@example.com
```

The script adds `{ admin: true }` to the user custom claims and creates/updates `users/{uid}` with `role: "admin"`.

The script uses the same service-account environment variables as the server application.

## 5. Deploy Firestore rules

Install the Firebase CLI if needed, then:

```bash
firebase login
firebase use <your-firebase-project-id>
firebase deploy --only firestore:rules,firestore:indexes
```

The rules are intentionally closed to public browser reads/writes. Public page rendering uses the Firebase Admin SDK on the server, while the admin UI is authorized through Firebase Authentication and the `admin` claim.

## 6. Run locally

```bash
npm run dev
```

Then open `http://localhost:3000`.

## 7. Build verification

```bash
npm run typecheck
npm run build
```

## Production hardening checklist

Before going live, replace all example policy wording with the publisher's approved legal/editorial policies, configure a real email delivery provider or help-desk workflow for contact messages, add a CAPTCHA/anti-abuse layer to the contact form, configure a custom B2 CORS policy, and set up a production backup/retention plan.

For DOI/Crossref, add DOI fields now (they already exist in the data model) and integrate Crossref only after you have the appropriate membership/depositor credentials and have confirmed the publisher metadata.
